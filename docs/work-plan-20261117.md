# 工作清单：从"能启动"到"流畅可用"

2026-11-17。按优先级排列。每条都有目标、做法、验收标准、回滚方式。一次只做一条，
不达标即回滚，不叠加实验。结论必须带数字与镜像哈希。

## 结论先行

- 掉帧与键盘输入延迟同源：**显示驱动的 buffer 往返是串行的**。
  实测每帧 = CA 产帧 10–17 ms + post 4–5 ms + CTL 确认 9.2 ms ≈ 22–30 ms。
- GPU 不是瓶颈：每帧仅忙 5–6 ms，有 3 倍余量。
- 参数不是瓶颈：`cpufreq`、Turnip 开关、`armcpu-self-ipi` 等已与参考对齐，帧时间不变。
- iPadOS 的 QuartzCore 没有 `CA_FORCE_TRIPLE_BUFFERED_LATENCY`（实测 `option=0 env=0`），
  macOS 的三缓冲/自由唤醒钩子在本板不存在。
- 壁纸缺失是独立缺陷：PosterBoard 在 `configuredPropertiesForPoster:` 断言崩溃
  （`PBFPosterExtensionDataStoreErrorDomain -2220`、沙盒报 `no system container path found
  for com.apple.PosterBoard`），与 GPU 无关。

## 为什么固件侧的几项能力我们没有

参考项目的固件是独立的 Renegade edk2 工程（`firmware-t970`），其中包含
`PlatformMemoryMap.c`（conventional memory + 640 MiB owned window）、固件内 `DarwinBootPkg`、
UEFI 菜单与按键、UFS handoff、vendor chain、low-FD MMU helper。

本仓库的固件是上游 Mu-Silicium（`4bd8ae83`）+ `scripts/prepare-uefi.py` 从上游 `r8qPkg`
派生的 `gts7xlwifiPkg`（CLANGPDB），厂商 DXE 从本机 XBL 提取。那份 Renegade 树不在本机，
所以这些能力只能照 XBL 实测数据自己写（`evidence/device-inputs/boot-firmware.json`）。

这些能力影响**可用内存与启动/存储组织**，不解释逐帧延迟；它们排在显示时序之后。

## P0-1 显示：swap 确认与 buffer 释放解耦

- 目标：CA 不再等上一帧 CTL 确认才产下一帧。
- 做法：`drivers/GopFramebuffer/NativeLegacyDisplay.cpp` 在帧 latch 进 scanout 时即回报
  swap 完成；IOSurface 加引用计数，持有到 CTL flush 确认后释放；整条路径由一个启动参数
  控制，默认关闭以便回滚。
- 验收：不花屏（先决条件）；`arrival + post + ack` 不再串行相加；平均间隔 ≤20 ms；
  >100 ms 停顿次数下降。
- 回滚：关闭参数即回到 `ca-archive-e`（`5a968b45…`）行为。

## P0-2 显示：真实 vblank，替掉定时器

- 现状：`NativeLegacyDisplay.cpp:112-115` 说明平台子类未随移植提供，GOP 扫描输出无 vblank
  中断，因此用 workloop 定时器假装 60 Hz vsync。
- 做法：优先查设备树中 DPU/DSI 可用中断并接 `native_legacy_vsync_notify`；否则把定时器改为
  绝对时间栅格（`mach_continuous_time` 推算、丢拍补偿），并测量 jitter。
- 验收：vsync 间隔标准差 <0.5 ms；帧间隔分布收敛；键盘输入到上屏延迟明显下降。
- 回滚：保留定时器实现，参数切换。

## P0-3 输入延迟定量

- 目标：确认键盘输入延迟在 P0-1/P0-2 后是否消失。
- 做法：用现有 touch/HID 计数器在 Wi-Fi 密码页测"触摸→上屏"端到端延迟。
- 验收：端到端 ≤ 2 帧（约 33 ms）。

## P1 固件内存图

- 目标：可用内存从 3.84 GiB 提高到接近 6.7 GiB。
- 做法：按 XBL 45 个平台区域与 13 个动态池窗口重建 conventional memory 导出，保留 display
  保留段与 FD/stack 布局，用现有 `t970-dram-end` 收口。
- 验收：`boot_args.memSize` 达到目标；连续运行 10 分钟无内存相关 panic。
- 风险：改错起不来；镜像内 FD 与内核一起回滚。

## P2 存储：UFS 原生可写

- 目标：对齐参考的 `ufsrw=1` / `t970-ufs-data=1`，不再依赖播种 APFS Data。
- 做法：沿已验证的 handoff 路径（CB0、SMR 55/56、DMA 在 owned window 内）先只读验证，再开写。
- 验收：重启后写入保留、fsck 通过。
- 风险：写坏分区不可逆，先备份并保留回执。

## P3 其他驱动

- Wi-Fi（QCA6390）：ath11k/MHI/QMI + 板级 PCIe 电源/PHY/MSI/DMA + 21H461 网络 ABI。
  验收：扫描→关联→DHCP→Safari 打开页面。
- 蓝牙：UART.SK 传输已链接。验收：配对键鼠。
- 音频：代码与参考一致。验收：扬声器与麦克风各一段录制回放。
