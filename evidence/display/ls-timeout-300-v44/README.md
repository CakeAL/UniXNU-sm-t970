# 延长终止报告：420 被拒，改用上限 300 秒

v42 的诊断显示不可中断线程会在 lsd 与 backboardd 之间换手，而 seeding 组等待与 LaunchServices 锁争用每轮都在。为区分"极慢但在前进"与"硬停顿"，本轮只改报告的终止时间，内核不变。

## 420 秒被内核拒绝

第一次按 420 秒打包（BOOT `2df53e121481824f…`）后实机立即进入诊断页，报告首行为：

```
runtime report interval invalid: 420 @kern_exec.c:8351
```

内核侧只接受 5–300 秒（`patches/xnu/t970-runtime-report.patch` 中的 `if (seconds < 5 || seconds > 300) panic(...)`）。这条保护有效，也把允许的上限确定下来：本轮改为 **300 秒**（BOOT `eb079f75b52c88c3…`），其余参数与 v42 完全相同。

## 判读方法

与同一内核的 v42（150 秒）逐项对照：

- 若 `n`（进程数）、`swap ok/bad`、`xfer/copies/retire`、`key-state calls`、`FB first-copy ms` 在 300 秒明显增长 → 系统是"极慢但在前进"，重点转向阻塞/性能；
- 若与 150 秒数值完全一致 → 硬停顿，回到不可中断线程的内核等待对象做 zone 或内核栈取证。

四次启动的 `publish → first-copy` 间隔分别是 125.9 / 140.0 / 153.4 / 147.4 秒，不是恒定值，因此不指向单一固定超时，更可能随负载累积，这一组 300 秒数据可以直接检验。

## 局限

单点采样只给终止瞬间的状态，中间过程没有记录；进程与线程集合在两次启动之间会变化，逐项对照只对同一内核版本有意义。
